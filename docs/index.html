核心项目 · 景点评论 RAG 问答系统

用 1749 条真实游客评论（151 个景点 · 10 城市）搭建的检索增强生成问答系统。 问它"带孩子去成都玩，推荐去哪"，它基于真实评论作答并给出原文出处。

  • 混合检索（BM25 + 向量 + 景点名精确匹配 → RRF 融合 → 多样性重排）在 Hit@1/3/5、Recall@5 四项全面优于任一单路。
  • 语义改写档是硬证据：先用脚本确认「纳凉」「老建筑」「古董」在语料中出现 0 次，再拿这些词提问 —— 关键词检索 Hit@5 = 0%，混合检索 80%。
  • 纯向量反而不如关键词基线（Hit@5 76.6% vs 83.0%）—— MiniLM 仅约 1.18 亿参数，中文细粒度区分度有限。这是选型事实，不是调参能绕过的。
  • 评测反查出两个真 bug：问"西安兵马俑值得去吗"，纯关键词检索 Top-10 全是"跟团游记"（标题有"兵马俑"三个字，而兵马俑自己的评论反而不含）⇒ 加景点名精确匹配后 T1 档 Hit@1 由 83.3% → 100%。

数据链路 · 城市景点数据分析

上一个项目的数据来源，与 RAG 项目构成「采集 → 清洗 → 分析 → 问答」的完整链路。

去哪儿网景点评论采集与分析 数据源头

  • 采集 10 个热门城市的景点评论，清洗后剩 1749 条 / 82 个有评论景点。
  • 内置数据质量自检：自动检测"景点名里含其他城市名"的跨城市污染记录，曾抓出 16 个可疑景点 / 330 条评论。
  • 第二轮发现更隐蔽的系统性误标（列表页"周边推荐"把邻市乃至全国景点带进来并打本地标签）—— 常规规则全部漏检，最终逐条人工核验。
